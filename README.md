# Projection UI — 웹 프로토타입

Figma `2026 개인 / UI` 섹션의 프로젝션 온보딩 플로우를 웹으로 옮긴 인터랙티브 프로토타입.
빌드 없음, 의존성 없음 — `index.html` / `style.css` / `app.js` 세 파일.

원본: [NEWTON GUI 작업](https://www.figma.com/design/m8cFjM9O4KoY3BeJswU1rJ/NEWTON-GUI-%EC%9E%91%EC%97%85) — 팩 시청 `705:7647`,
Level/Mode `205:10018`, Main workout `143:7373`, Total 컨테이너 `759:8520`.

## 실행

```bash
python3 serve.py        # 5555번, 다른 포트는 python3 serve.py 8080
# http://localhost:5555
```

`python3 -m http.server`를 쓰면 크롬이 `app.js` / `style.css`를 캐시해서 새로고침해도
옛 코드를 보고 있을 수 있다. `serve.py`는 같은 서버에 `Cache-Control: no-store`와
**Range 응답(206)**을 붙인 것. Range가 없으면 크롬 미디어 로더가 책상 영상을 아예 못 붙잡고
(readyState 0에서 멈춘다) 스크러빙도 안 된다. GitHub Pages는 원래 Range를 지원한다.

> 영상이 안 나오면 **탭이 보이는 상태인지** 먼저 확인할 것. 크롬은 백그라운드 탭에서
> 비디오 디코드와 rAF를 멈추므로, 가려진 창에서는 코드와 무관하게 영상이 전부 멈춘다.

localhost에서 열면 `index.html` / `style.css` / `app.js`의 `Last-Modified`를 1초마다 폴링해
자동 새로고침한다. 파일 저장하면 브라우저에 바로 반영됨 — 이때는 **보고 있던 화면에 그대로**
머문다.

**새로고침(⌘R)하면 항상 첫 화면부터 다시 시작한다.** 선택했던 카드도 전부 초기화되고
히어로 영상도 처음부터 재생된다. 특정 화면만 바로 열려면 `?at=level`처럼 붙인다
(`pack` `watch` `location` `condition` `injury` `level` `main`).

자체 점검: `http://localhost:5555/index.html?selftest` → 콘솔에 PASS/FAIL.
결과는 `window.__selftest` 배열에도 들어간다.
동작뿐 아니라 **핵심 치수(스크롤 프레임 360×413, 히어로 360×519.5, Total 360×171, 바 105/210)**도
같이 검사한다 — 이 값들이 계속 어긋났기 때문.

## 종이 뷰 + 2K 익스포트

합성용 룩과, 그 룩으로 테이크를 통째로 뽑는 익스포터.

```bash
node scripts/export.mjs                      # out/PAPER_2K.mov + .mp4 (2560×1440 / 30fps)
node scripts/export.mjs --w 3840 --slow 28   # 4K
```

서버·크롬은 스크립트가 알아서 띄우고 내린다. 브라우저에서 룩만 보려면
`http://localhost:5555/index.html?look=paper`.

**룩 값은 `style.css`의 `body.is-paper` 네 줄이 전부다.**

| | 값 |
|---|---|
| 투사면 `--paper` | `#A7AFC1` |
| 글자 `--gray` | `#6B6B6B` — 배경 위든 카드 위든 한 색. `--white`는 그대로 둔다(빨간 칠 위 글자) |
| UI 전체 투명도 `--dim` | `.88` |
| 사진 투명도 `--photo` | `.5` — 뒤에 흰 판(동그란 사진은 흰 아웃라인)을 깔고 얹는다 |

**화면녹화가 아니라 익스포터다.** 해상도는 디스플레이와 무관하고 드롭이 0이다. DOM은
three.js처럼 가상 시계를 꽂을 수 없어서(CSS 애니메이션이 컴포지터 시계로 돈다) 페이지를
`--slow`배로 늦춰 돌리고 한 장씩 찍은 뒤 출력에서 제 속도로 되돌린다. 늦춰야 하는 시계는 넷:

- CSS 애니메이션·트랜지션 → CDP `Animation.setPlaybackRate`
- `setTimeout`/`setInterval` → 지연에 배수를 곱한다 (테이크의 `gap`이 여기 있다)
- `performance.now`/rAF → 스케일된 시각 (스크롤 글라이드·숫자 트윈)
- `<video>` → `playbackRate`. **1/16 = 0.0625가 크롬의 하한**이라 `--slow` 기본값이 16이다.
  더 늦추면 영상만 이 속도에 머물러 UI와 어긋난다

한 장 찍는 게 예산(`slow/fps`)보다 오래 걸리면 그만큼 내용이 앞서가므로, 끝나고 최대
드리프트를 ms로 보고한다. 0이 아니면 `--slow`를 올린다.

PNG 시퀀스는 남기지 않는다 — 2K 740장이면 2.5GB짜리 중간산출물이라 ffmpeg에 바로 물린다.
`.mov`(ProRes 422, ~230MB)가 에펙에 넣을 본편, `.mp4`는 확인용.

## 팩 제안 캐러셀

양옆 카드는 임시 이미지가 아니라 **중앙 카드와 같은 컴포넌트**(`#packTpl`)의 복제다.
내용은 `app.js`의 `PACKS` 배열 한 곳에만 있으므로 팩을 추가·수정할 때 마크업을 손댈 필요가 없다.

- 중앙 기준 **좌우 대칭**으로 배치되고, `.deck`의 `perspective: 1400px` + 슬롯의
  `translateZ`/`rotateY`로 약한 투시가 들어간다. 크기는 손으로 줄이지 않고 Z로만 멀어지므로
  원근이 어긋나지 않는다
- **스와이프**(드래그 44px, 또는 트랙패드 좌우 플릭)하면 그 방향 카드가 중앙으로 온다.
  손을 뗄 때가 아니라 **44px을 넘는 순간 바로** 넘어간다 — 터치 면에서는 이게 맞고,
  pointerup이 안 오는 환경에서도 동작한다
- **옆 카드를 탭**해도 중앙으로 온다. 중앙 카드의 View Pack만 상세로 넘어가고,
  옆 카드의 버튼은 그 카드를 중앙으로 가져오는 역할만 한다
- 팩 제안 화면에 다시 들어오면 항상 중앙(보싱 팩)으로 되돌아간다
- 중앙 카드 뒤에는 `blur.svg`(=`assets/blur-glow.svg`)의 **레이어 블러 + 백그라운드 블러**가
  깔린다. 두 레이어 모두 중앙 자리에 **고정**이고 z-index 7 — 옆 카드(6)보다 위, 중앙 카드(9)보다
  아래다. 그래서 뒤에 있는 카드가 실제로 블러되고, 스와이프할 때 블러가 카드를 따라 움직이거나
  매 프레임 다시 합성되지 않는다. 원본은 타원으로 하드 클립하는데 이 크기에서는 옆 카드에
  경계선이 그려져서, 같은 타원을 부드러운 마스크로 바꿨다
- 이미지는 **레포에 이미 있는 사진을 임시로 돌려쓴 것**이다. 썸네일 프레임이 가로로 길어서
  인물 머리가 잘리기 쉬우므로 `PACKS[].pos`로 컷을 하나씩 잡아뒀다 (중앙 보싱 팩은 `50% 10%`).
  실제 스톡 사진으로 바꿀 때는 `assets/`에 넣고 `PACKS`의 `img`와 `pos`만 고치면 된다

## 녹화용 기본값 · 프로토타이핑 커서

첫 진입 시 배경 `#A6A6A6`, **프로젝션 프리뷰 켜짐**으로 뜬다. 프로젝션 프로토타이핑을 여기서
그대로 녹화하기 위한 상태다.

- **커서** — 프레임 안에서는 시스템 포인터를 숨기고 반투명 원형 커서를 그린다. 자체 rAF
  루프에서 지수 스무딩(프레임당 0.16)으로 따라가므로, 녹화본에는 마우스의 날것 떨림이 아니라
  미끄러지는 커서가 남는다. 36px, 채움은 **위 #FFFFFF 100% → 아래로 투명해지는 그라디언트**.
  헤어라인은 두 겹이다 — 어두운 데서는 밝은 선이, 밝은 데서는 아주 옅은 어두운 선이 남는다.
  누르면 살짝 작아지고 채움이 진해진다
- **커서는 프레임 안 어디서도 손모양으로 바뀌지 않는다.** `.stage *`로 눌러도 `button`,
  `.slot`, `.hit`에 붙어 있던 `cursor:pointer`가 이겨서, 그 셋을 직접 걷어냈다
- **드래그해도 파란 텍스트 선택 영역이 생기지 않는다** (`user-select:none`)
- **터치 이펙트** — 누른 자리에서 얇은 링이 1.7배까지만 퍼지며 사라진다 (0.42s)

커서와 탭은 스테이지 안(디자인 좌표)에 있으므로 프레임과 함께 스케일된다.

`#A6A6A6` 배경에서는 계측값이 **배경 위 텍스트 2.0:1**로 뜬다 — 지금 다크 테마의 흰 글자
기준이다. 라이트 필드를 같이 켜면 같은 배경에서 약 8.9:1이 된다.

## 책상 영상 위에 얹기 (하단 패널)

`assets/desk.mp4` — `Projection GUI.mov`(4096×2160, 2:42)를 1920폭 h.264로 줄인 원본 플레이트(5.7MB).
`ffmpeg -i "Projection GUI.mov" -an -sn -vf scale=1920:-2 -c:v libx264 -crf 26 -movflags +faststart assets/desk.mp4`

**페이지가 재생하는 건 `assets/desk-cut.mp4`(1:03, 3.0MB)** — 촬영자가 가이드로 놓았다 뺐다 한
클리어 파일이 **중심에 없는 구간만** 모아 크로스 디졸브(0.6s)로 이어붙인 것.

검출은 눈이 아니라 값으로 했다. 용지 자리(`crop=250:190:700:560`)의 `signalstats.YAVG`가
파일이 있으면 ~201, 없으면 ~186으로 갈린다 — 히스테리시스 196/191로 자르면 12개 구간이
나온다. 각 경계에서 0.6초씩 깎고, 동작이 안 담긴 2.2초짜리 첫 토막을 버리면 **11개 구간**.
`xfade`로 이었다.
`잘라내기` 원리 그대로라 재현 가능하다:

```bash
ffprobe -f lavfi "movie=desk.mp4,fps=5,crop=250:190:700:560,signalstats" \
  -show_entries frame=pts_time:frame_tags=lavfi.signalstats.YAVG -of csv=p=0
```

**전체화면이 아니라 프레임 안에서 작업한다.** `.canvas`가 그 프레임 — 고정 비율로 잘라낸
"샷"이고, 녹화되는 건 이 안쪽뿐이다. **기본은 `원본` 비율 · 배율 100%로, 아무것도 잘리지
않는다** — 얼마나 잘라낼지는 정해주는 게 아니라 고르는 것이다. 비율은 원본 / 16:9 / 16:10 /
4:3 / 1:1 / 9:16, **크롭**(배율 · X · Y)이 영상의 어느 부분을 담을지 정한다. `전체화면` 버튼은
문서가 아니라 이 캔버스만 전체화면으로 올린다 — 패널은 샷에 들어가지 않는다.

영상은 **배경 이미지가 아니라 캔버스 안에 들어있는 판**이다. 프로젝션 프리뷰가 그 위에
합성돼야 하기 때문 — 그래야 화면에 보이는 것이 "책상 목업 위의 UI"가 아니라 **실제 책상에
실제로 투사된 결과**가 된다. 검정은 광량 0이라 그 자리에는 진짜 책상이 그대로 비친다.
`?selftest`가 이 위치를 검사한다.

- **재생 / 일시정지** — 버튼 또는 스페이스바(입력 요소에 포커스가 없을 때)
- **타임라인** — 드래그로 스크럽
- **컷** `[` 현재 위치를 시작으로, `]` 끝으로, `✕` 해제. 타임라인에 빨간 띠로 표시된다.
  끝에 닿으면 **컷 반복**이 켜져 있으면 시작으로 되감고, 꺼져 있으면 멈춘다
- **컷 내보내기** — 브라우저에서 4K를 재인코딩할 이유가 없으므로, 그 컷을 무손실로 잘라내는
  `ffmpeg -ss … -to … -c copy` 명령을 클립보드에 넣는다. 원본 파일에 대고 그대로 실행하면 된다
- **전체화면** — 문서 전체를 전체화면으로. 패널이 거슬리면 각 패널 우측 `–`로 접는다

### 투시 (같은 패널 아래줄)

카메라가 책상을 비스듬히 보고 있으므로, 화면에 정면으로 그려진 프레임은 책상 위에 놓일 수 없다.
7개 노브가 프레임을 눕힌다 — **기울기**(rotateX) · **좌우**(rotateY) · **회전**(rotateZ) ·
**원근**(perspective) · **크기** · **X** · **Y**.

**드래그 정렬**을 켜면 프레임을 끌어서 옮긴다. `Shift`를 누르고 끌면 영상 크롭이 움직인다.
슬라이더로 찾는 것보다 두 그림을 겹치는 데는 이쪽이 빠르다.

### A4 가이드

GUI는 2560×1600이지만 촬영 때 책상에 **A4를 가로로** 깔고 기준을 잡았다. GUI가 그 가로폭
297mm에 딱 맞으면 GUI 높이는 `297 ÷ 1.6 = 185.6mm`이고, A4 210mm에서 위아래로
**12.2mm씩** 남는다. 디자인 단위로 A4는 `1060 × 749.49`, 여백 띠는 각각 `43.25`.
그 두 띠를 옅은 흰색으로 깐 것이 가이드다 — 영상 속 실제 A4에 겹치면 투사 위치가 촬영
때와 같아진다. 흰 책상에서는 옅은 흰색이 안 보이므로 A4 외곽선을 얇은 레드 헤어라인으로
같이 그린다. `A4 가이드` 체크박스로 끈다.

> 참고로 현재 `desk.mp4` 속 용지는 **세로로** 놓여 있다. 화면상 안쪽 깊이/가로 = 0.84인데,
> 가로로 눕힌 A4는 어떤 각도에서도 0.707을 넘을 수 없다(기울이면 줄어들기만 한다).
> 가이드는 지시대로 가로 기준이니, 이 영상에 겹치려면 드래그 정렬로 맞춰야 한다.

가이드는 프레임과 **같은 커스텀 프로퍼티를 읽는 형제 요소**다(둘 다 캔버스에 붙은 값을
상속). 그래서 투시를 어떻게 돌리든 둘은 항상 붙어 다닌다. `?selftest`가 이걸 검사한다.

기본값은 `desk-cut.mp4`에 맞춰 손으로 찾은 정렬값이다 —
**기울기 31° · 좌우/회전 0° · 원근 2148px · 크기 32% · X −33 · Y +61**,
크롭은 **16:9 · 배율 100%**.

> 값은 화면 px이라 **찾을 때의 창 크기에서만** 그대로 맞는다. 다른 크기에서는 드래그 정렬로
> 다시 얹으면 된다. 촬영 중 카메라가 조금씩 흔들리기도 해서 어차피 완전 고정은 불가능하다.

> **원근은 기울기가 0°면 아무 효과가 없다.** 카메라를 정면으로 마주 본 평면에는 투영될 깊이가
> 없기 때문 — 죽은 컨트롤처럼 보였던 이유다. 이제 기본값이 눕혀진 상태라 바로 반응한다.

`perspective()`는 부모가 아니라 `.stage`의
transform 안에 들어있다: 부모는 책상판이고, 책상은 이미 카메라의 투시를 갖고 있으므로 같이
기울면 안 되기 때문. 값은 `localStorage`에 저장된다 — 새로고침은 플로우를 처음부터 다시
시작시키므로, 맞춰 놓은 정렬까지 날아가면 곤란하다. `리셋`으로 되돌린다.

프레임이 기울면 포인터→디자인 좌표가 **사영변환**이 되어 배율 나눗셈으로는 커서가 어긋난다
(중앙은 맞고 모서리로 갈수록 벌어진다). `unproject()`가 z=0 평면에서 행렬이 무너지는 3×3
호모그래피를 역으로 푼다. `?selftest`가 기울인 상태에서 왕복시켜 검사한다.

## 오토 플레이 모드 (오른쪽 패널)

컷에 남긴 11개 구간마다 손이 책상으로 한 번씩 뻗는다. 그 11개가 비트다.

**시각은 측정값이다.** 컷 영상의 손끝을 추적해서(차가운 책상 위에서 따뜻한 건 피부뿐이라
`R−B`로 키잉된다) 가장 깊이 뻗어 머무는 구간의 한가운데 — 손가락이 닿아 있는 순간 — 에 비트를
놓았다. `desk-cut.mp4`를 다시 만들면 이 값도 바뀐다.

**순서는 플로우 그대로다.** 캐러셀이 첫 화면이고 첫 터치가 그걸 넘긴다:

| 비트 | 시각 | 동작 |
|---|---|---|
| 1 | 2.4s | **스와이프** — 캐러셀이 `7m Indoor Boxing`으로 넘어간다 (손이 왼→오른쪽으로 가므로 카드는 **왼쪽에서** 들어온다) |
| 2 | 9.1s | 카드 열기 → 팩 상세 |
| 3 | 13.2s | **드래그 스크롤** |
| 4 | 18.6s | Start → Location |
| 5·6 | 23.0 · 28.7s | **Indoor** · **Standard** → 자동으로 Condition |
| 7 | 34.6s | About the Same as Usual → 자동으로 Injury |
| 8 | 40.1s | **None** (몸 그림에 마커 없음) → 자동으로 Level |
| 9·10 | 46.2 · 51.2s | Standard · Recommended → 자동으로 Main workout |
| 11·12 | 58.1 · 58.7s | 라운드 + 두 번 → **6** |

마지막 구간은 한 번의 긴 터치(57.9–59.0s)라 두 탭이 그 안에 들어간다.

오토 플레이에서는 덱이 `7m Indoor Boxing` **한 칸 오른쪽**에서 시작한다 — 첫 터치가
스와이프인 이상 도착할 데가 있어야 하고, 손이 가는 방향과 카드가 오는 방향이 맞아야 한다.
손으로 볼 때는 여전히 그 팩이 가운데다. `?selftest`가 이 둘의 방향 일치를 검사한다.

### 손이 UI를 가림

프로젝터는 책상 위에 있고 손은 그 사이에 있다. 그러니 **손이 지나가는 자리는 투사된 것이
가려져야** 한다. 이게 없으면 프레임이 팔 위에 그려져서 "두 영상을 겹쳤다"로 읽힌다.

**베이스 영상에는 손이 없다.** `assets/desk-clean.mp4` — 같은 마스크로 손 자리를 클린
플레이트로 덮어버린 판이다. 손은 오직 위에 얹히는 매트에서만 온다. 아래에도 손 사본을
남겨두면 두 클립이 한 프레임만 어긋나도 **손이 두 개로** 보이고, 매트의 부드러운 가장자리
틈으로 UI가 비쳐 **희끄무레한 테두리**가 생긴다. 둘 다 이걸로 사라진다.
(마스크를 8번 팽창시켜 이음매가 맨 책상에서 잘리게 했다 — 손 살결 근처에서 자르면 그 선이 보인다.)

`assets/hand-matte.webm` — 손이 없는 **빈 책상 프레임과의 차분**으로 뽑은 매트. h.264는
알파를 못 실으므로 **VP9 + `yuva420p`**(크롬이 지원)로 인코딩한다. 프레임 위에 같은 박스·같은
크롭·같은 `object-fit`으로 얹으니 아래 플레이트와 픽셀 단위로 맞아떨어진다 — 애초에 같은
클립이니까.

매트는 **원본 4K에서 2880폭**으로 다시 뽑는다(베이스는 1920). 샷이 2.5배 확대되는 클로즈업이라
1920 소스는 화면에서 1.6배 업스케일되고, 그만큼 손 가장자리가 물러진다. 매트만 1.5배
해상도로 올리면 같은 박스에 `object-fit:cover`로 얹히므로 정합은 그대로다.

매트는 **차분 AND 살색** 두 조건을 모두 만족하는 영역이다. 빈 책상과 다르면서(`blend=difference`)
동시에 따뜻한(`R−B`) 픽셀만 남긴다 — 차분만 쓰면 손 그림자까지 통째로 들어와 UI를 크게
가리고, 살색만 쓰면 그늘진 손가락 옆면을 놓쳐 알파가 너덜너덜해진다.

가장자리는 **일부러 딱 떨어지게** 잘랐다(임계 폭 5). 반투명 림을 두면 그 틈으로 UI가 비쳐
손 둘레에 밝은 후광이 생긴다. 아래 플레이트에 **똑같은 손이 이미 있으므로** 경계를 하드하게
잘라도 이음매가 보이지 않는다 — 매트 밖 1~2픽셀은 플레이트의 손이 받아준다.

인코딩은 **`crf 30`**, 8MB대. 처음 봤던 블록은 해상도가 아니라 `crf 38`이 원인이었다 —
같은 화질을 1.5배 해상도에서 얻으므로 압축률은 오히려 올려도 된다.

플레이트는 컷 **안**의 빈 프레임(31.0s)을 쓴다. 원본 도입부(2.0s)의 빈 책상도 깨끗하지만,
노출이 미묘하게 달라서 책상에 적힌 파란 표시와 흐릿한 손까지 오검출로 떠올랐다 — 클립
전체와 시간적으로 가까운 프레임이 결과가 낫다. 매트는 책상 영역(`Y>400`)으로 제한한다.
그 위는 방과 프로젝터라 어느 플레이트를 써도 다 다르게 나온다.

> 손 **그림자**도 매트에 들어간다. 그림자는 프로젝터 빛이 실제로 막히는 자리이므로 거기서
> UI가 사라지는 게 맞다.

같은 편집을 두 개가 디코드하는 건 비용이다. 재생·정지·시크를 같이 걸고 0.08초 이상
어긋나면 되돌린다 — 매 프레임 합성하는 것보다 싸다. `?selftest`가 매트가 프레임 **뒤가
아니라 위**에 있는지, 아래 플레이트와 같은 변환을 쓰는지 검사한다.

> 실제로는 프로젝터 빛이 손등에도 떨어지고 손은 책상에 그림자를 만든다. 둘 다 이 합성에는
> 없다 — 가림만 넣었다.

### 커서는 진짜 손가락을 탄다

`assets/hand.json` — 컷 영상의 **검지 끝**을 10fps로 추적한 좌표(플레이트 기준 천분율, 손이
없으면 `null`). 손이 왼쪽 위를 향하므로 가장 위쪽 행들 중 **왼쪽 20퍼센타일**이 검지다 —
평균을 쓰면 두 손가락 사이를 짚어서, 허공에서 손이 지나가는 것과 검지로 누르는 것이
구분되지 않는다. 오토 플레이에서 디스크는 이 궤적을 따라간다.

**디스크는 마우스 포인터가 아니라 터치 자국이다.** 손가락이 책상에 닿는 순간에만 있어야
한다 — 비트 **앞 0.55초부터 뒤 0.45초까지**만 보이고 나머지 시간에는 없다. 손이 프레임에
있기만 하면 보이게 했더니 손을 뺄 때 디스크가 따라 나갔는데, 그건 터치 자국이 절대 하지
않는 동작이다.

비트 순간에는 **손끝 그 자리에서** 눌린다 — 컨트롤 위로 끌고 가지 않는다. 디스크는 추적된
손끝을 타고 있고, 버튼으로 튀는 건 영상에 없는 움직임이다. 작아졌다가(19px) 놓으면서
원래 크기로 돌아오고 탭 링이 퍼진다. 스와이프·스크롤은 손가락이 지나온 직선을 잔상으로
남긴다(0.55초 전 손끝 → 지금 손끝).

손 매트가 프레임 위에 있으므로 손끝에 찍히는 링은 손가락 밑에 상당 부분 가려진다. 투사면에
찍힌 자국을 손이 가리는 건 실제로 일어나는 일이라 그대로 뒀다 — 링을 손보다 크게 키우면
디자인에 없는 크기가 된다.

플레이트 좌표 → 디자인 좌표는 `unproject()`를 거친다. 영상 요소가 크롭과 샷 변환을 이미
달고 있으므로 그 클라이언트 박스에 `object-fit:cover`를 되짚으면 화면 좌표가 나온다.

### 샷은 프로젝션 중심으로 자동 크롭된다

오토 플레이를 켜면 `.shot`(영상·A4·프레임을 함께 감싼 레이어)이 프레임의 투영된 박스가
캔버스의 74%를 채우도록 밀어 넣고 그 중심을 가운데로 놓는다. 영상만 크롭하면 프레임이
따라오지 않으므로 **한 겹 위에서 같이** 움직인다. 창 크기나 투시를 바꾸면 다시 계산한다.

`unproject()`는 이제 `shot × frame` 두 행렬을 곱해서 푼다. 둘 다 같은 중심을 기준으로 하니
그대로 합성된다.

영상이 끝나면 플로우를 처음으로 되감고(선택·라운드 수까지) 다시 돈다. 타임라인을 뒤로 끌면
되감은 뒤 지나간 비트를 애니메이션 없이 즉시 재적용한다.

> **제스처 인식이 아니다.** 클립은 UI가 없는 맨 책상에서 찍혔고, 영상에서 모든 손동작은
> 똑같이 읽힌다 — 들어와서, 머물고, 빠진다. 어떤 손짓이 무엇을 "의미"하는지는 애초에 영상에
> 없으므로 여기에 **작성**한 것이다. 시각만 측정값이다.

**Next를 누르지 않아도 넘어간다.** 한 단계의 모든 그룹에 답이 차면 0.9초 뒤 자동으로 다음
단계로 간다(선택이 보이고 나서 넘어가도록). 오토 플레이와 무관하게 항상 그렇다.
`onSelect`에 달았지 `refreshNext`에 달지 않았다 — 후자는 화면 진입에도 돌아서, 이미 채워진
단계로 되돌아오면 즉시 다시 튕겨 나간다.

## 프로젝션 배경색 테스트

우측 하단 패널의 색은 **책상 색**이다. UI가 칠하는 배경 같은 건 없다 — 정해진 요소(카드·텍스트
·그래프)만 투사되고, 그 외 영역은 전부 맨 책상이다. `--bg`는 그 책상 색을 담는 토큰이고,
프리뷰에서는 스테이지가 아예 배경을 칠하지 않아 책상판이 그대로 드러난다.

프리셋: Design default(#141414) · Neutral/Black · Neutral/800 · White desk · Warm desk · Wood desk.
헤더의 `–`로 접힌다. 배경은 `--bg` 하나만 바꾸므로 나머지 토큰은 그대로다.

### 프로젝션 프리뷰 — 원본을 농도로 얹는다

같은 패널 아래쪽 **프로젝션 프리뷰** 체크박스.

처음엔 `mix-blend-mode: screen`이었다. 물리적으로는 그게 맞다 — 프로젝터는 빛을 더할 뿐
뺄 수 없다. 문제는 흰 책상에서 더할 여유가 거의 없다는 것이고, 그러면 디자인의 색이
통째로 씻겨 나간다. 흰 카드도 책상, 레드도 분홍이 된다.

지금은 **원본을 그대로 얹되, 밝기에 따라 투명도만 다르게 준다.** 일반 합성(`normal`) +
필터 `#tone`. 한 장에 균일한 불투명도를 주면 검정이 붙여넣은 것처럼 뜨기 때문에 —
**검정 50%, 화이트 80%**, 그 사이는 값에 따라 이어진다. 값 = `R+G+B`(1에서 클램프)이라
`#FA3030`(1.36)은 화이트와 같은 80%로 남는다. **색은 하나도 리매핑하지 않는다.**

> 프레임 자신의 **투명 배경은 투명 그대로**여야 한다. 필터가 그걸 "검정 픽셀"로 세면
> 프레임 전체가 50% 회색 판이 된다. 마지막에 `feComposite operator="in"`으로 원래 알파를
> 다시 곱하는 이유다 — 투사하지 않는 것과 검정을 투사하는 것은 다르다.

> **UI에는 원본에 없는 선을 절대 그리지 않는다** — 리얼 프로젝션뷰의 테두리는 삭제했다.

| 노브 | 뜻 | 기본 |
|------|-----|------|
| 책상 | 책상 자체의 색 (프리셋 + HEX) | `#A6A6A6` |
| 환경광 | 방이 얼마나 밝은가 = 검정 자리의 밝기 | 18% |
| 프로젝터 | 투사 광량 (밝기) | 100% |
| 농도 | 표면이 디자인을 얼마나 받는가 | 92% |

**브랜드 레드의 사전 보정도 없앴다.** 가산 합성을 거꾸로 풀어 플로어가 들어올린 채널을 미리
빼두는 계산이었는데, 합성이 더 이상 가산이 아니다. 일어나지도 않는 들뜸을 보정하면 레드가
반대로 밀린다. 손대지 않는 것이 곧 원본 색이다.

### 리얼 프로젝션뷰

환경광을 빼고 **책상을 고른 색 그대로** 깐다. 프리뷰는 `책상 × 환경광`, 리얼은 `책상` 그대로.
그리는 방식은 프리뷰와 완전히 같다.

### 발광 영역만 보기

프로젝션에서 검정은 색이 아니라 **광량 0**이다. 그래서 프레임 자신의 배경은 프리뷰에서
투명이고(프레임이 칠하는 배경은 없다), 그 자리에는 책상이 그대로 온다. 다만 **디자인 안의
검정은 검정으로 그린다** — 원본과 달라지지 않는 쪽을 택했다.

패널의 **발광 영역만 보기**를 켜면 책상판이 체커보드로 바뀌어서, 빛이 나가는 픽셀과
나가지 않는 픽셀이 그대로 갈린다. 지금 디자인에서는 배경 전체가 체커(=투명)로 비고
카드·타이틀·플로우 바만 남는다 — 프로젝터가 책상에 얹는 건 딱 그것뿐이라는 뜻이다.

### 라이트 필드 (흰 책상용 극성)

패널의 **라이트 필드** 토글. 흰 책상에서는 어두운 배경을 쓸 수 없으므로 극성을 뒤집는다 —
**필드가 빛나는 쪽, 글자가 빛나지 않는 쪽**이다. 카드도 같은 이유로 어두워진다: 밝은 필드 위의
흰 카드는 대비가 1.1:1이라 아무것도 못 하지만, 어두운 카드는 빛에 뚫린 구멍이라 맨 책상으로 읽힌다.

필터가 아니라 **토큰 교체**다. 이걸 위해 `--white`/`--black`에서 역할 셋을 분리했다 —
밝은 필드에서는 카드 채움과 그 위 글자가 서로 반대 방향으로 가야 하기 때문이다:

| 토큰 | 뜻 | 다크 | 라이트 |
|------|-----|------|--------|
| `--surface` | 카드·패널 채움 | `--white` | `#1B2426` |
| `--ink` | 배경 위 글자 | `--white` | `#10181A` |
| `--ink-2` | 카드 위 글자 | `--black` | `#F2F4F4` |
| `--bg` | 투사 필드 | `#141414` | `#E5E6E6` |

`--white`/`--black`은 문자 그대로의 뜻을 유지하므로 **레드 그라디언트 위 흰 글자와 선택 이펙트는
양쪽 테마에서 그대로**다.

계측값: 배경 위 글자 14.4:1, 카드 위 글자 14.3:1 — 다크 테마와 같은 수준이다.

**아직 남은 것** (방향 확정 후 Figma에서 정리 필요):

- `--n400`/`--n500`은 필드 위와 카드 위에 모두 쓰여서 지금은 절충값이다
- Start 버튼 뒤 글로우는 흰빛이라 밝은 필드 위에서는 거의 사라진다 — 라이트에서는
  글로우 대신 어두운 링/그림자 역할을 할 무언가가 필요하다
- 아이콘 버튼(북마크·공유)과 Rounds/Time 세그먼트가 어두운 면 위 어두운 면이라 대비가 약하다
- Assist Mode 카드처럼 **비트맵으로 구워진 아트**는 토큰을 따라오지 않는다
- 브랜드 레드는 필드 대비 3.0:1 — 큰 면적은 괜찮지만 그 위의 작은 글자는 피해야 한다

### 가독성 계측

같은 패널에 주요 조합의 명도 대비가 실시간으로 뜬다. 프리뷰가 켜져 있으면 **투사 결과**
(디자인을 플로어 위에 screen한 값)로 계산하므로, 지금 고른 배경에서 흰 텍스트가 살아남는지
숫자로 바로 확인된다. 4.5:1 미만은 빨갛게 표시된다.

배경 후보를 넣어보면:

| 배경 | 흰 텍스트 / 배경 |
|------|------------------|
| `#141414` (디자인 기본) | 11.1:1 |
| `#0E1C24` (딥 틸) | 약 9:1 |
| `#E5E6E6` (밝은 필드, 다크 테마 그대로) | **1.2:1** |
| `#E5E6E6` + 라이트 필드 토글 | 14.4:1 |

`#E5E6E6`에서 흰 텍스트가 안 읽히는 건 프로젝션 문제가 아니라 그냥 대비 문제다(모니터에서도
같다). 밝은 배경을 쓰려면 **글자를 어둡게 뒤집어야** 한다 — 그리고 그게 흰 책상에서
물리적으로도 맞는 방향이다. 어두운 글자 = 광량 0 = 맨 책상 = 낼 수 있는 가장 어두운 값이므로,
밝은 필드 위에서 확실히 어둡게 읽힌다. 반대로 흰 글자는 필드보다 밝을 수가 없다.

### 색 보정은 필터가 아니라 투명도로

토큰을 다시 계산하지 않는다. 규칙은 **원본 색을 그대로 두고 투명도를 낮추는 것**이다.
색상·명도가 그린 그대로 유지되고, 가산 합성이 끝나면 낮아진 알파가 알아서 플로어에 가까워진다.
한때 토큰별로 명도·채도를 재계산했는데, 그러면 **비활성 탭마다 색이 달라진다** — 같은 상태인데
제각각으로 보이는 게 그 때문이었다. 프리뷰의 노브는 물리값 셋(책상·환경광·프로젝터)만 남았고
스테이지에 걸리는 필터는 프로젝터 게인 하나뿐이다.

플로우 바가 그 규칙의 기준 사례다:

- 비활성 스텝은 **`--white`를 40% 투명도로** 쓴다. 두 번째 색이 아니다. 디자인 배경 위에서는
  Figma가 지정한 Neutral/500과 같은 값으로 떨어지고, 투사되면 플로어 기준으로 알아서 맞는다.
  색상 이동이 없고, 규칙이 하나고, 비활성 스텝끼리 완전히 동일하다
- 현재 스텝만 투명도 100% + bold. 지난 단계를 따로 낮추는 3단계는 넣지 않는다 —
  Figma가 2단계만 규정하고, 요청도 "현 단계가 가장 잘 보이고 남은 단계는 살짝 낮추기"였다
- Next도 같은 규칙: 답이 없으면 40%, 채워지면 100%
- 선택 카드의 드롭섀도는 프리뷰에서 끈다. 그림자는 빛을 빼는 것이고 프로젝터는 그걸 못 한다

## 팩 시청 (`705:7647`)

레이아웃은 노드 좌표 그대로다. 히어로 360×519.5 @(140,72) r40, 정보 블록 @(576,124),
Start 버튼 328폭 @(576,521).

- **스크롤 영역은 상단 뒤로가기 탭 아래 프레임부터**다 — (560,124)에서 **y=537**까지 360×413.
  537은 Figma가 이 프레임을 클립하는 선이고, Start 버튼 바로 아래다. 정보 블록·스탯·콘텐츠가
  함께 스크롤되고, **고정되는 건 뒤로가기 탭·히어로·Start 버튼 세 개뿐**이다.
  프레임 바닥(663)까지 늘렸더니 버튼 아래로 콘텐츠가 내려가서 회색 판으로 덮어야 했고,
  그게 "뒤로 뭔가 이상하게 비치는" 것이었다. 537 아래에는 배경·글로우·버튼만 있다
- 히어로는 썸네일로 시작해 **1초 뒤 클립이 크로스 디졸브**로 들어오고, 새로고침 전까지 반복 재생
- 프레임 하단의 흐린 효과는 **4단 progressive blur**다 (2 / 6 / 14 / 26px). 마스크를 씌운
  backdrop-filter 한 장은 자기 윗변에 항상 경계선을 만든다 — 마스크는 레이어를 페이드시키지만
  블러는 여전히 엘리먼트에서 잘리기 때문에 그 선 양쪽의 필터가 다르다. 블러와 마스크가 함께
  단계적으로 올라가면 어느 한 변도 눈에 띄는 변화를 지지 않는다
- **Start 영역 뒤 (노드 `705:7786`)** — Figma에 키프레임은 없고, 효과 자체가 모션이다.
  타원은 462×154, 180° 회전, 중심 (728,541)이고 `blur.svg`의 585×277은 그 상자에 레이어 블러
  30.72(사방 61.5)가 붙어 커진 크기다. 그래서 배치가 `435.5 / 402.5`. 5.5초 주기로 밝기와
  크기가 아주 조금 숨쉰다 — 이 프레임에서 살아 있는 유일한 빛이다
- 백그라운드 블러는 **타원(462×154) 안에만** 13px으로 들어간다. 585×277 박스 전체에 걸면
  카드 위쪽의 분(minute) 숫자까지 흐려진다 — 그 박스는 타원에 레이어 블러 여백이 붙은 크기다
- 스크림은 **layer blur 62 + background blur 2**. 62px는 스크림 자체에 걸린 블러라서 경계선
  없이 프레임에 녹아든다. 어둡게 깔지 않는 것이 중요하다 — 원본에서 그래프 카드는 버튼 아래로
  **밝은 회색으로 블러**되고, 어두워지는 건 카드 바닥(y=602)을 지난 뒤부터다. 그 아래는
  스크림은 스크롤 프레임 하단에만 얹히고 같은 선에서 끝난다 — 그 아래는 가릴 것이 없으므로
  단색 판도 없다. 스크림 색은 `--bg`를 따라가므로 배경을 흰 책상으로 바꿔도 회색 띠가 남지 않는다
- 팩 카드의 HOT 배지에도 프로젝트 불 아이콘이 들어간다 — 원래 🔥 이모지를 렌더하고 있었다
- 불 아이콘은 `solar:fire-bold-duotone` 에셋 2개 (24px, 18.67px 13.68° 회전).
  Figma가 레이어 블러를 구워서 내보내므로 필터를 걷어내야 선명하게 나온다.
  **프로필 스택보다 위 레이어**다 (Figma도 하단바 다음에 쌓여 있다)
- 불꽃은 프로필 근처에서 **살짝 떠올라 멀어지면서 사라진다** (3.2s linear, 두 개가 1.6s 엇갈림).
  이동 거리는 17px뿐이다 — 처음엔 64px를 ease-out으로 보냈더니 확 튀었다가 기어가는 것처럼
  뚝뚝 끊겨 보였다. 스케일 변화도 없앴다.
  **하단은 선명하고 불꽃 끝(상단)으로 갈수록 블러리한** progressive blur — 같은 아트를 세 겹
  쌓아 각각 마스크 밴드와 블러 강도를 다르게 줬다 (0 / 0.9px / 2px). 마스크가 서로 겹쳐서
  세 단계가 아니라 그라데이션처럼 읽힌다

## Main workout (`143:7373` · `759:8520`)

**Total은 조작란이 아니라 표시용**이다. 오른쪽 Set up의 Rounds / Time이 Strike 시간을 정한다.

- 팩의 STRETCH 5분 · LEARN 7분은 고정
- 휴식은 라운드 **사이**에만 들어간다: Strike = 라운드×3m + (라운드−1)×1m.
  6라운드 → 23m, Total 35m (`205:10083`과 일치)
- Set up을 건드리기 전까지 그래프는 디자인의 105 / 210 / full 폭을 유지하고,
  Strike 시간이 정해지는 순간 **세 바가 모두 분에 비례하는 폭으로 실시간 재배치**된다.
  위 두 바가 줄어들고 Strike가 자란다 (0.5s)
- 분 숫자는 빨간 바 **안에** 들어간다. 바가 96px보다 좁아지면 STRETCH/LEARN 라벨을 떨어뜨리고
  분만 남긴다 (`205:10083`의 처리와 동일)
- 큰 분 숫자와 `min`은 둘 다 **왼쪽 정렬**이다 (노드의 두 텍스트가 같은 x=10)
- 숫자는 스냅하지 않고 **굴러 올라간다**. 크기가 커지는 팝은 없다 — 같은 크기에서 수만 오른다.
  스텝 진입 시 Total이 0→값까지 700ms,
  −/+로 바뀔 때는 Total 450ms · 라운드 260ms · Strike 분 450ms.
  탭이 숨겨지면 rAF가 멈추므로 진행 중인 트윈은 목표값으로 바로 착지시킨다
- 세 바는 모두 같은 램프(`--bar-ramp`)를 각자 폭에 걸쳐 쓴다 — 끝 색이 전부 같아진다.
  STRETCH 바만 반대 방향이라 옅은 청록 꼬리가 보였던 문제가 이걸로 없어졌다

## 실루엣

Injury check의 인물은 `assets/injury-silhouette.mp4`. 원본이 **흰 매트 위 주황 실루엣**이라
`app.js`가 매 프레임 캔버스에서 흰 배경을 알파로 키잉한다 (`FLOOR`/`GAMMA`로 조절).
덕분에 배경색을 어떤 색으로 바꿔도 실루엣이 살아있다.

키잉 루프는 `requestVideoFrameCallback`이 아니라 **rAF**로 돈다. rVFC는 영상이 디코딩할 때만
불리므로 탭이 한 번 숨겨지면 루프가 영영 죽고 캔버스가 빈 채로 남는다 — 값들을 이것저것
만지다 보면 실루엣이 사라지던 원인이다. rAF는 페이지와 함께 자고 깨고, 클립이 멈춰 있으면
루프가 스스로 다시 재생시킨다.

바닥 링과 좌우 아이콘은 **같은 주기·같은 위상**(3.2s)이다. 아이콘이 미끄러지는 동안 링이
살짝 기울어서 하나의 동작으로 읽힌다. 서로 다른 주기로 어긋나며 지나가던 것이 불편했던 부분.

부위별 위치는 `app.js`의 `PARTS` 테이블 하나에 정규화 좌표로 모여 있다. 클립을 다시 찍으면
이 표만 고치면 된다.

## 구조

프레임은 Figma와 동일한 **1060 × 663** 고정 크기. `.stage`를 뷰포트에 맞춰
`transform: scale()`로만 축소하므로 모든 좌표·타이포가 디자인 값 그대로다.

디자인 토큰(색, 그라디언트, 그림자, 타이포)은 `style.css` 상단 `:root`에 Figma 값 그대로 들어있다.
Figma에 등록된 `selected` 이펙트 = drop shadow `0 15px 58.32px 10px #0000000D` +
inner shadow `0 0 16px 6px #FFFFFF99`. **inner shadow는 채움 레이어 위에 얹어야** 보인다 —
그라디언트나 선택 아트가 위를 덮으면 사라지므로, 카드·칩·Assist 카드 모두 최상단 레이어에 걸었다.

- 프로젝터 앰비언스: 상단 빔 + 미세 플리커
- `prefers-reduced-motion` 존중

## Newton 앱 프로토타입과 공유하는 것

같은 디자인 시스템을 쓰는 [figma-prototype](https://github.com/dab2n/figma-prototype)에서
이미 개발된 규칙을 그대로 가져왔다 (원본은 읽기만 했고 아무것도 바꾸지 않았다):

- **체크 배지** — `assets/check-circle.png`. 에셋이 그림자를 투명 여백으로 갖고 있어
  52px 박스가 28px 원을 그린다. 모든 카드(Location·Today's Goal·Condition·Assist Mode)에
  일관되게 붙고, 난이도 세그먼트와 부위 칩에는 붙지 않는다
- **선택 토글 방식** — 한 번 더 누르면 해제. 단일 선택 그룹도 라디오처럼 동작하되 끌 수 있다
- **Assist Mode 선택 그림자** — 라이브러리의 58px/10px 그림자는 작은 카드에서 회색 띠로 보여서
  앱과 같이 `0 5px 14px rgba(0,0,0,.10)` + 흰 inner glow로 좁혔다. 선택되면 Recommended
  배지 자리를 체크가 대신한다
- **Next 활성화** — 답이 채워지기 전엔 Neutral/500, 채워지면 화이트
- **신체 부위 좌표** — 앱의 `injury-map`에 있는 값(312×554 기준)을 그대로 정규화해서 썼다.
  같은 클립이라 두 프로토타입이 어긋나지 않는다

## 폰트

- 본문 전체 **Supreme** (Fontshare)
- 큰 분(minute) 숫자만 **OffBit Trial Dot Bold** — Figma에서 지정한 그 스타일 하나만 쓴다.
  `assets/fonts/OffBitTrial-DotBold.otf`로 번들되어 있다. 트라이얼 폰트이므로 배포 전
  라이선스 확인 필요.

## 알려진 차이

- 실루엣 부위 좌표(`PARTS`)는 클립의 한 프레임 기준 고정값이다. 영상 속 인물이 움직이므로
  팔·다리가 크게 움직이는 구간에서는 마커가 살짝 어긋난다.
- 아이콘 중 북마크·공유는 인라인 SVG, 나머지(체크·신발/맨발·바닥 링·화살표·±·뒤로·셰브론)는
  전달받은 에셋 또는 Figma 내보내기.
- 프로젝션-터치 환경이라 **호버 애니메이션은 전부 제거**했다 (우측 하단 컬러 패널은 개발용
  크롬이라 예외).
